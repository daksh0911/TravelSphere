🎓 5. Master Viva Voce Q&A Cheat Sheet (Top Questions & Answers)

Q1: What is the core problem TravelSphere solves?
"Most travel applications isolate booking from supplier operations. TravelSphere provides a unified platform using Role-Based Access Control (RBAC) connecting travelers with agents, hotels, transit providers, guides, and platform administrators in a synchronized system."
Q2: Why React 19 and Vite 8 instead of plain HTML/JS or traditional Create-React-App?
"React offers component-based architecture and a reactive Virtual DOM for zero-latency dashboard state updates. Vite replaces legacy Webpack bundling with native ES modules, compiling our build in under 1 second with automatic route-based code splitting."
Q3: How do you prevent unauthorized users from accessing the Admin panel?
"Through dual-layer protection: on the frontend, React Router wraps protected routes with a custom <ProtectedRoute allowedRoles={[...]}> guard checking authenticated tokens. If unauthorized, users are immediately redirected. On the backend, Express/Flask API middleware verifies HMAC session tokens and rejects unauthorized requests with HTTP 403 Forbidden."
Q4: How is the database organized and normalized?
"Our travel_db consists of 19 normalized relational tables in Third Normal Form (3NF). Core identity tables (users, admin) connect to resource tables (packages, hotels, vehicles) and transactional tables (bookings, payments) via Foreign Key constraints."
Q5: Why did you choose MySQL instead of MongoDB (NoSQL)?
"Tourism management requires strict ACID guarantees (Atomicity, Consistency, Isolation, Durability) for financial bookings and payments. Foreign keys prevent orphan records (a booking cannot exist without a valid package and user), ensuring absolute financial data integrity."
Q6: How does the application prevent SQL Injection attacks?
"We enforce Parameterized Prepared Statements (using ? placeholders in Node.js mysql2/promise and %s tuples in PyMySQL). The database engine compiles the query template first; user input is treated strictly as data literals and can never execute as SQL code."
Q7: How are user passwords secured?
"Passwords are hashed using salted cryptographic bcrypt with work factor 10 ($2b$10$...). bcrypt incorporates a unique salt per password, rendering precomputed rainbow table and dictionary attacks computationally infeasible."
Q8: What is Database Connection Pooling?
"Instead of establishing a heavy new TCP socket connection to MySQL for every incoming HTTP request, a connection pool maintains a pool of reusable active connections. This eliminates connection overhead, reduces latency, and prevents server exhaustion under traffic spikes."
Q9: How do you handle Cross-Site Scripting (XSS)?
"React automatically escapes string variables within JSX before rendering to the DOM. Additionally, the backend enforces Content-Security-Policy (CSP), X-Content-Type-Options: nosniff, and X-Frame-Options: DENY security headers."
Q10: Did you conduct automated testing?
"Yes. We have a 59-test automated test suite executed via Node's native test runner (npm test) that audits session token security, RBAC boundary isolation, pricing algorithms, and input sanitization in under 600ms."
Q11: What happens if a user loses internet connectivity while browsing?
"The application utilizes client-side caching with localStorage fallback state and static Single Page Application (SPA) fallback routing (404.html), allowing travelers to inspect saved itineraries and vouchers even with intermittent network connection."
